# Evidence entailment follow-up

The observed failure is an unsupported intermediate claim in an otherwise
appropriately cautious answer. Footer formatting alone cannot detect it.
Package diagnostics also allowed a model to overstate local probes as runtime
correctness. These are distinct problems with distinct verification boundaries.

## Change

1. Replace overlapping general reminders with a compact procedure: identify
   missing evidence before concluding; test only plausible alternatives that
   affect a material conclusion; keep the conclusion on surviving evidence;
   preserve the same scope in headline, body and footer. State supported facts
   plainly. Keep detailed examples in the technical skill and reference.
2. Generate doctor headline and Checked/Gap/Next text from typed results.
   Skills render these fields verbatim. Package checks, isolated delivery and
   current-session activation remain separate. This part has deterministic tests.
3. Preserve literal custom triggers, bypasses and stateless advisory hooks.
   Reject an automatic second model or blocking Stop validator: neither can
   establish generic truth, and both change the runtime/privacy contract.

Competing explanations: missing logical bridges, lost scope during summary,
footer/body inconsistency, and diagnostic wording delegated to the model.
The mixed local harness and model variability remain possible contributors;
this work does not establish why a remote configuration behaved differently.

## Bounded behavioral validation

The independent Fable design review rejected a closed list of expected claim
IDs as sufficient to score all prose. Use blinded independent full-answer
adjudication instead: inspect headline, intermediate assertions, verdict basis,
footer and any unanticipated factual assertion. Exact supporting answer quotes
must match in memory; derive offsets locally, without whitespace normalization.
Missing or ambiguous matches are unscorable, not passes.

Author and hash the synthetic case packet before editing instructions. This is
a predeclared transfer/regression packet, **not an independently held-out set**.
Do not claim generalization from it. Cover prerequisites/outcomes, feature/build
identity, sampled coverage, causation, source conflict, corrected dependencies,
supported narrow positives, and routine/creative negatives. Include existing
coverage/measurement behavior when replacing guidance.

Calibrate the independent reviewer on authored good/bad answers first, including
an unlisted assertion, misleading headline, unwarranted denial, footer-masked
overclaim, supported plain statement, conditional recommendation, doctor scope,
swapped answer and instruction injection. Require critical controls to agree
with the authored oracle before scoring live answers. Opus is the subject;
Fable is the requested independent adjudicator alias (resolved identity may be
unavailable). Repeat blinded adjudication unchanged and report disagreements.
Audit all answers for missed assertions rather than only reported failures.
Raw answers stay in memory; save only fixed labels, counts and validated metadata.

Each subject session loads exactly one accuracy plugin version, in a separate auth-only
temporary profile. Attest init plugin/tool/MCP inventories, model identity and
hook delivery. Candidate and released version use identical model/settings;
pin medium effort and record provider-default sampling. The host also reports a
`telemetry` plugin in an auth-only no-plugin probe; record and match this shared
host component rather than claiming a completely plugin-free runtime. Reject
other inventory differences. Infrastructure
or activation failure excludes the pair from both denominators. The bounded
driver stops and leaves the entire stage unscored when this happens; any
instrumentation repair and subsequent repeat must be disclosed separately.

Ramp one plumbing pair, then three distinct families. Stop comparative expansion
on a clear null/ceiling; additional positive and regression controls then serve
only compatibility checking. Repeat critical cases once without tuning. Preserve
failed runs and scorer disagreements; do not pool attempts into a desired score.
Acceptance requires supported positive conclusions without extra hedging, no
judged unsupported assertions in the declared packet, consistent corrections,
and no routine/creative footer. A failure gets one reasoned revision and bounded
retest; repeated failure limits or removes the candidate instead of expanding an
unbounded prompt search. Model judgments remain fallible even when calibrated.

## Release gates

Doctor presentation is independently testable and need not wait for a broad
accuracy-lift claim. Full repo gates, clean install, independent Fable and
explicit Opus review, required Codex review, CI and guarded publication remain
necessary. Report measured scope and intrinsic advisory limitations. The
separate experimental analytical-review PR is outside this change.
