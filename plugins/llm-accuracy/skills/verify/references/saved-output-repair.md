# Repair saved outputs against evidence

Apply this check when revising a saved report or explaining changes to earlier
versions. Use the source material and the actual saved versions available in
this task. On a host without file access, use supplied snapshots and name the
access limit; do not claim to have opened or executed a check on a local file.

1. Separate three questions: what the current source supports, what each earlier
   saved version actually contained, and what the evidence shows about the
   correction. A source update is not proof that the earlier report was wrong
   under its then-current source. Preserve original versions and their identities.
2. Check the full required fields, not just totals: IDs, dates, statuses,
   membership, ranking, units, denominators and scope. Recompute calculations
   using a deterministic tool when available. Equal counts do not prove equal
   members. Keep contact availability distinct from queue eligibility or rank.
3. Bind each proposed correction to the exact earlier claim, its source-bound
   contradiction and the replacement. Preserve correct values, supported scope
   limits and conditional statements. A wording preference or equivalent audit
   representation is not an error. If no contradiction is established, describe
   a clarification as a clarification, or omit it.
4. Check correction explanations as factual claims. Earlier contents establish
   what was written, not how it was produced. A wrong input next to a correct
   result does not establish that the result was calculated from that input.
   Claim a cause, derivation, tool execution or missing check only when available
   process evidence supports it. Otherwise report the observed discrepancy and
   leave its origin unknown. Do not manufacture a causal story to explain a fix.
5. Keep historical contents faithful even when they were wrong. Explain their
   correction separately. Do not substitute the current value into a historical
   record or claim a clean earlier version after silently removing its error.
6. Inspect the actual final saved file after writing it, when the host permits.
   Recheck both its required data and its prose, including the audit, closing
   note and delivery summary. A structured validator's pass covers only its
   declared fields; it does not certify narrative truth or process claims. If a
   subsequent edit changes the file, repeat the affected checks on those bytes.
   State unavailable checks precisely rather than inventing a pass or failure.

Deliver the requested report and a concise, truthful account of material
corrections. Do not add an audit ceremony when a small correction suffices.
