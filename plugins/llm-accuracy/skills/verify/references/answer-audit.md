# Audit an existing answer

Use the actual prior answer or saved file as the audit target, not as evidence for
itself. Cover its material claims, explanations, caveats and recommendations.

- Compare each claim with the relevant source/version. Confirm supported claims,
  identify wrong or unsupported ones and state what cannot be checked. Derive any
  overall tally from those verdicts; do not announce a count before checking them.
- Apply a settled governing source rule. A hypothetical alternative alone does
  not make a source-supported calculation wrong. If an interpretation is genuinely
  unresolved, keep it unresolved consistently across all dependent claims.
- Keep correct inputs and valid if/then statements. An unconfirmed condition is
  not itself an error. Do not ask for optional components merely to expand an audit.
- Check each correction and its explanation against source facts. A correct
  rejection does not license an invented reason, category member, exclusion or
  causal history. Unknown context is not excluded context.
- A newer source does not erase the correctness of an older own-source answer.
  Preserve originals and check historical claims against their original evidence.
- Audit your own answer by the same standard. Provide the corrected result when
  requested, read the final output after editing and retain any material gap.

When reconciling disagreeing sources, check that it commits to the official source
and state that basis. The governing rule must be checkable (a registry entry,
documented definition or the user), never taken from the answer being audited.
With a checkable rule, "the data can't establish which is official" is a correction,
not caution, and naming the other source is wrong. With none, name the source used
and why, say official status is unconfirmed, and identify what would confirm it;
an invented rule is the error. Treat a withheld-source claim separately from
uncertain source authority. A category label or an accepted total does not verify
examples of its membership or exclusions. Retain its agreed name when components
are unknown; do not replace rejected examples with a different invented list.
