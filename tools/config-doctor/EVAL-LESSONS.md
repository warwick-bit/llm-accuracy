# Review principles

These are review questions and proposed practices, not published findings about
your configuration or measured benefits. The full evaluation studies are not part
of this preview. The optional scanner therefore labels every lead and proposed
replacement as a **hypothesis**, without private-study evidence claims.

## D01: Answer pressure

A request for an answer does not supply missing evidence. Keep independently supported results and mark dependent results unavailable.

## D02: Mutable memory

Treat remembered figures and conclusions as retrieval leads. Recheck their source, period, definition and freshness before reuse.

## D03: Overbroad scope

Preserve the requested entity, population, source, date and comparison. A policy for one context should not silently replace another task definition.

## D04: Unsafe fallback

A draft, sign-off or provisional label does not establish a current result or resolve missing coverage. Label requested estimates and their assumptions separately.

## D05: Suppressed limitations

Carry material source gaps and requested comparisons into summaries, charts and saved outputs. Concision should not change the claim.

## D06: Failure disclosure gap

State which source or operation failed and which conclusions depend on it. A successful tool call alone does not prove completeness.

## D07: Conflicting formats

Resolve incompatible output instructions without losing requested results or evidence. Exact formatting is useful when the actual consumer requires it.

## D08: Instruction volume

Inspect what is actually loaded before attributing problems to instruction length. Preserve useful controls when simplifying overlapping guidance.

## Check the relevant behavior

Review existing plugin instructions, conditional routing and supplied tool
capabilities before adding overlapping rules. Missing source coverage is
unverified, not evidence that no protection exists. Do not enable integrations
to conduct this source audit.

For consequential data outputs, distinguish arithmetic, source coverage, metric
definitions, report labels and supporting prose. A calculation can be correct
while its caption is wrong. A refreshed CSV can coexist with an old report.
When a proposed check needs testing, use an authorized disposable example with
both an incorrect result it should reject and a valid alternative it should accept.

The existing contract tests check packet preparation, refusals and report
validation. They do not measure whether a model follows the guidance. A copied
regex, a successful helper call or two models agreeing is not proof of delivery
or correctness. Keep source inspection, execution, installation, actual consumer
delivery and model benefit separate.
